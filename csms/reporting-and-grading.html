Reporting, grading and client updates

What Skillable can tell you about learners, how grading works, and what to say to clients when something goes wrong.

Audience
CSMs and program ops
Time
8 min read

What you can report on

Skillable records every lab instance (each individual launch). For each one you can see:

  • Learner, class and lab
  • How long the lab was open
  • Completion status: complete, incomplete or canceled
  • Score and pass/fail, where the lab is scored
  • Answers given to questions, and the correct answers
  • Output captured by automated checks (where the lab is set to show results in reports)

TMS also tracks progress within a lab, based on how many task check boxes the learner has ticked.

How to pull it

Use Admin, then Labs, then Find Lab Instances (or Exam Lab Instances for scored labs). Filter by class, and save the search as a default view so weekly reporting is one click. Select Details on a lab for question-by-question results.

Step by step in Skillable’s docs: Viewing lab instances

Access: CSMs are expected to have the Operations Manager role, which also lets you enroll last-minute learners and connect them to classes. If you can’t see the Labs tile for reporting, ask the lab admin to update your role.

Useful weekly signals for client updates

Signal Where What it tells you
Labs launched vs enrolled learners Find Lab Instances, filtered by class Attendance in practice
Completion status Same Who finished vs who left early
Time in lab Same Engagement depth
Canceled labs Completion status = canceled Possible frustration or lost work. Follow up
Scores (if used) Exam Lab Instances Skill attainment

Caution

“Time in lab” includes idle time until timeout. Treat it as a rough signal, not a metric to put in front of a client on its own.

How grading works

So you can explain it to a client:

  • Grading in Skillable is built from activities inside the lab: questions (multiple choice, short answer) and automated checks that inspect the learner’s environment.
  • The LED specifies which activities count, their point values and the passing score. The lab admin configures them in Studio.
  • Checks can award partial credit.
  • Learners may see nothing, their score only, or a full breakdown, depending on how the lab is set.
  • Labs can be practice (unscored, retries allowed) or assessment (scored, sometimes only on submission).

Scoring is decided per program by the client and the LED. Some programs score labs; others use them purely for practice.

When something goes wrong

Triage

Symptom Likely cause Route to
Can’t sign in Wrong email, not enrolled, password CSM (check enrollment)
Class not visible Enrollment status or class not started CSM (check enrollment)
Lab won’t launch for one person Network / browser / pop-ups Instructor → tech check
Lab won’t launch for everyone Platform issue Check → Lab admin
Tool missing or broken on VM Image issue Lab admin
Learner lost work Exited without pushing / canceled Instructor; re-clone from GitHub

Client messaging principles

  • Lead with what we’re doing and when the learner will be back working.
  • Lost-work incidents: own the gap in onboarding, then point to the push-to-GitHub routine as the fix going forward.
  • Platform outages: during the lab admin’s hours, route through GA. After hours or for deliveries in other time zones, instructors and CSMs email GA’s Skillable priority support address (see Who to contact). GA has Skillable’s premium support tier, so tickets are picked up right away.
