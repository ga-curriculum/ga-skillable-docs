Updating this site

How to edit a page, add a page, add a client and publish. You don’t need to know how to code.

Audience
Whoever maintains the Skillable guides
Time
8 min read

This site is a folder of ordinary files. Each page is one .html file, and the look of the whole site is one .css file. There’s no build step and nothing to install. Edit a file, save it, refresh your browser.

What you need: a plain text editor (VS Code is ideal; Notepad or TextEdit in plain-text mode also works). To publish for a team, a GitHub account.

Which file do I edit?

I want to change… Edit this file
The words on a page That page’s .html file
Who to contact for help (name and email) assets/js/site-config.js
The TMS sign-in link, the support link or the status link assets/js/site-config.js (change it once and every page updates)
The menu, or a page’s title or summary in the sidebar and section pages assets/js/site-config.js
A screenshot Save a new PNG over the old one in assets/screens/
Colors, fonts, spacing assets/css/styles.css
The version and date in the footer assets/js/site-config.js

You should never need to edit assets/js/site.js. It builds the sidebar, progress tracking and footers.

How the folders are organized

index.html           The home page
get-started/         Get started: what Skillable is, signing in, glossary
instructors/         For instructors
lab-authors/         For LEDs and SMEs
csms/                For CSMs
help/                This page and the screenshot list
_templates/          Copy these to make new pages
assets/
  css/styles.css     The look of the site
  js/site-config.js  Menus, contact details, shared links
  js/site.js         Behind the scenes (don't edit)
  screens/           Screenshots (PNG files)
  files/             Downloads, such as the lab template
  img/ and fonts/    Logos, images and fonts

Keep every page inside its folder. The pages find the shared files by their location, so moving a page to a different depth breaks its links.

Edit the words on a page

  1. Open the page’s .html file in your text editor.
  2. Find the banner that says EDIT THE PAGE CONTENT BELOW THIS LINE. Everything between it and STOP EDITING HERE is the page’s content.
  3. Change the words between the tags. Keep the tags themselves, the bits in < >.
  4. Save and refresh the page in your browser.

The title area at the top of each page (the <h1> headline, the paragraph under it, and the “who it’s for” line) is also yours to edit. Leave the other parts of the file alone.

The one rule

Each opening tag needs its closing tag. If you delete <p> you must delete its </p> too. When a page looks strange after an edit, a missing closing tag is almost always the reason.

Copy-and-paste building blocks

Copy one of these, paste it where you want it, and change the words.

A heading

Each <h2> heading appears in the “On this page” list automatically.

<h2>Heading text</h2>

A paragraph, with bold and a link

<p>Some text with <strong>bold words</strong> and a <a href="../instructors/faq.html">link to another page</a>.</p>

Links to other pages use ../ to step out of the current folder, then the folder and file name.

Bullets

<ul>
<li>First point</li>
<li>Second point</li>
</ul>

Numbered steps

<ol class="steps">
<li><strong>Short step title.</strong> A sentence of detail.</li>
<li><strong>Next step.</strong> More detail.</li>
</ol>

A callout box

Use callout for neutral notes, callout warn for anything that could lose someone’s work, and callout tip for helpful extras.

<div class="callout warn">
<span class="callout-title">Watch out</span>
<p>Push to GitHub before you exit the lab.</p>
</div>

A table

<div class="tscroll">
<table>
<thead><tr><th>Column A</th><th>Column B</th></tr></thead>
<tbody>
<tr><td>One</td><td>Two</td></tr>
<tr><td>Three</td><td>Four</td></tr>
</tbody>
</table>
</div>

A question and answer

Put several of these inside one faq block. Visitors click a question to open its answer.

<div class="faq">
<details>
<summary>The question?</summary>
<div class="answer"><p>The answer.</p></div>
</details>
</div>

Cards that link to other pages

<div class="cards">
<a class="card" href="../get-started/glossary.html"><h3>Card title</h3><p>One line about the page.</p></a>
</div>

A checklist people can tick

Ticks are remembered in each visitor’s own browser.

<ul class="checklist">
<li><label><input type="checkbox"><span>Do this thing</span></label></li>
</ul>

A code block

Visitors get a Copy button automatically. Write &lt; instead of < inside code.

<pre><code>git add .
git commit -m "what changed"
git push</code></pre>

A shared link or the lab admin’s details

These fill in from site-config.js, so you change them in one place. Leave the link empty and it shows the address.

<a data-link="tms"></a>
<a data-link="speedTest"></a>
<a data-link="support"></a>
<a data-link="status"></a>
<a data-link="docs"></a>
<span data-site="labAdminName"></span>
<a data-link="labAdminEmail"></a>

Add screenshots

Wherever a screenshot is missing, the site shows a dashed Screenshot to add box. To fill one, save your screenshot as a PNG with the exact file name shown in the box and put it in assets/screens/. The full list, with exactly what to capture for each, is on Screenshots to take.

To hide the dashed boxes until the files exist, set showPlaceholders: false in assets/js/site-config.js.

Change the menu, contact or shared links

Open assets/js/site-config.js. It’s a list with plenty of comments. Keep the double quotes and the commas, and don’t put a double quote inside text.

Add a new page

  1. Copy the template. Copy _templates/new-page.html into the right folder, for example instructors/. Give it a short name with no spaces, like new-hire-checklist.html.
  2. Fill in the title area and the content.
  3. Add it to the menu. Open assets/js/site-config.js and add a line like the example below inside the right group.
  4. Open the page in your browser and check the sidebar and the Next button at the bottom.

Example menu entry:

{ file: "instructors/new-hire-checklist.html", nav: "New hire checklist", title: "New hire checklist for instructors", summary: "One sentence about what it helps you do.", time: "3 min", who: "New instructors", keywords: "onboarding new hire" },

Change colors or fonts

Open assets/css/styles.css. The brand colors and fonts are at the top, in the block called :root. Change a value there and it changes everywhere.

Publish it

Share as files. Zip the whole folder and send it. Anyone can unzip it and double-click index.html. It works offline in any modern browser.

Publish with GitHub Pages, so the team has one address:

  1. Create a repository on GitHub, for example skillable-at-ga. It can be private if your plan supports private Pages. Otherwise anyone with the link can read it.
  2. Upload the whole folder’s contents, keeping the folders as they are. index.html must sit at the top level.
  3. Turn on Pages. Go to Settings → Pages, choose Deploy from a branch, select main and / (root), and save.
  4. Wait a minute or two. GitHub shows the site’s address, usually https://your-account.github.io/skillable-at-ga/.
  5. To update, edit a file and commit it. GitHub republishes automatically.

Links to a single page work too, for example .../instructors/faq.html. Copy them from the browser’s address bar.

If something looks wrong

  • A page has no menu or sidebar: the page can’t find assets/js/site-config.js. Check that the page is still inside its folder and the file name is unchanged.
  • The whole menu disappeared after an edit to site-config.js: a quote or comma is missing. Undo your last change.
  • Part of a page is missing or oddly formatted: a closing tag was deleted. Compare with a page that works.
  • A change doesn’t show up: refresh your browser with Ctrl+F5 (Cmd+Shift+R on a Mac).
  • Printing: every page prints cleanly. Use your browser’s Print or Save as PDF.
