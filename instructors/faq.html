Quick reference

Labs aren’t persistent by default, which is behind most of the questions below. Each answer links to the page with the full detail.

The basics

Is the lab machine the learner’s to keep?

Not by default. Every launch is a fresh copy of an image GA built, and the copy is deleted when the lab ends.

Some programs use saveable labs for a period, so a machine can be paused and resumed. Which one applies is a program decision. Ask the program’s CSM.

A quick test: if the Exit menu only shows End, that lab can’t be saved.

What’s the single most important habit?

Commit and push to GitHub before leaving any lab, every time.

Do learners need to install anything?

No. They need a modern browser, a network that allows Skillable, and pop-ups allowed for the TMS site.

Can I see learners’ screens?

Yes. Open Monitor Labs from your Class page to see every running lab, then use Monitor Student to watch or Take Control to work in their lab. Steps are on During class.

Does launching a test lab affect learners?

No. Your test lab is ephemeral too, so changes you make never reach learners. Report image problems to the lab admin.

Instructors can hold up to 5 saved labs (7-day save) for demos and prep.

Saving, ending and timeouts

What’s the difference between Save and Close, End and Cancel?
  • Save and Close keeps the machine so the learner can resume later. It only appears on labs where saving is turned on.
  • End finishes the lab and deletes the machine.
  • Cancel throws the work away. The next launch starts fresh.
A learner clicked Cancel. Can we get the work back?

No. The instance is gone. Have them re-clone from GitHub, then re-run their setup.

A learner closed the lab tab. Is the lab still running?

Yes. By default it keeps running for 60 minutes after the window closes. They can relaunch from TMS to reconnect.

How long before a lab times out?

Lab duration is set per lab. The defaults for the other timeouts are a 15-minute idle timeout (warns, then shuts down) and a 60-minute closed-window timeout. Programs can ask for different values.

Tell learners at the start of each session how long the lab runs and remind them to respond to timeout warnings. See the full table on How labs work.

How many saved labs can people hold, and for how long?

Learners can hold 2 saved labs and instructors 5. Save periods for instructor-led classes are typically 7 days. Saves expire, and reopening and saving again pushes the date out. GA can ask Skillable for different periods.

Will Skillable save the lab automatically if a learner goes quiet?

There is some auto-save behavior for inactive labs, but don’t rely on it. It depends on lab settings and timing, and an active lab that simply runs out of time won’t auto-save. GitHub is the backup plan.

Environment variables and what gets lost

An environment variable is a named setting inside the lab machine, such as an API key, that tools can read. Because every launch starts from a fresh copy of the image, anything a learner sets by hand lives only as long as that terminal or that machine does.

I set an environment variable (or an API key) and now it’s gone. Why?

Two common reasons.

  1. It was set in a terminal. A variable set by hand in a terminal normally lasts only for that terminal session. A new terminal may not have it.
  2. The machine is a fresh copy. Each launch starts from the original image. Files, installed packages and keys set in the shell from a previous machine don’t carry over. Only what is built into the image, or injected by GA at launch, is there.

The fix is to set it again at the start of each fresh session. If every learner needs it, ask the lab admin whether it should be built in or injected at launch. See Request a lab change.

Which variables does GA set for learners automatically?

Keys that GA injects at launch (for example, an API key for a coding assistant) are set automatically as environment variables in the terminal. Learners never see or handle them, and nothing is distributed to them.

Which ones a program has depends on the program. Ask the lab admin.

Where should a learner keep their own keys and secrets?

Never commit secrets to GitHub. Keys go in environment variables, or in a .env file that is listed in .gitignore.

Because a .env file is deliberately kept off GitHub, it won’t exist on a fresh machine. Learners re-create it, or re-set the variable, at the start of each fresh session. On a saved lab it stays until the save expires.

Is this the same as the @lab.… placeholders in lab instructions?

No. Tokens such as @lab.User.FirstName are placeholders in the lab instructions, filled in when the learner launches the lab. Variables like @lab.TextBox(name) collect a value from the learner inside the instructions. Environment variables live inside the machine, in the terminal. See the authoring guide.

A tool asks learners to sign in instead of using the preset key. What now?

The key is probably not present in that session. Have the learner open a new terminal and try again. If it persists, relaunch the lab, then contact the lab admin.

A tool stops with a usage or limit error.

The program’s API usage limit has been reached. Contact the lab admin.

git push asks for credentials or fails.

The learner isn’t signed in to GitHub on this machine. Run gh auth login. Sign-ins don’t carry over to a fresh machine, so this is part of every fresh-session routine.

Tools and packages

A package is missing after the learner relaunched.

If it isn’t in the base image, or was installed on a previous fresh machine, it won’t be there. Install it again (for example with pip install). If every learner needs it, tell the lab admin so it can be built into the image. New tools and packages need about 3 days’ notice: see Request a lab change.

A tool is missing, or the wrong version, for everyone.

That’s a base image issue, so contact the lab admin. Don’t have learners install workarounds unless you’re told to. The next fresh machine won’t have the workaround, and it may hide a problem every learner will hit.

In class

What should I tell learners at the start and end of every session?

Start: name the exact lab to launch, then show the start-up routine (clone or pull, sign in, set keys).

End (15 minutes before): commit, push and confirm on GitHub. Then Save and Close or End, as the program specifies.

More in During class.

A learner lost their work. What now?

If they pushed to GitHub, they git clone (fresh machine) or git pull and carry on. If they didn’t, the work on the machine can’t be recovered after End, Cancel or an expired save. Use it as a teaching moment for the whole class, not just the learner.
