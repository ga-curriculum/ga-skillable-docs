When something goes wrong

Triage, the fix order, common problems, who to contact and how to reach Skillable support.

Audience
Instructors and TAs during live sessions
Time
8 min read

Triage first: three questions

Question What the answer points to
How many learners are affected? One: their device or network. Several in one location: that network. Everyone: the platform
What do they see? A black screen, a connection message, lag, an error, or a lab that won’t launch
Constant or intermittent? Intermittent usually means connectivity

If everyone is affected, check before anything else.

The fix order for a misbehaving lab

Work down this list. Stop as soon as it’s fixed.

  1. Reconnect (machine menu in the lab window) for a black, frozen or disconnected desktop. The machine keeps running.
  2. Refresh the page (F5) for a stuck instructions pane, or if Reconnect didn’t help.
  3. Relaunch from TMS if the lab window was closed or the first two steps didn’t work. A running or saved lab resumes where it was.
  4. Reset or reboot the machine only if it’s hung. Unsaved work in open apps may be lost. If it keeps happening, stop and contact Skillable support.
  5. Cancel and relaunch only as a last resort. This wipes the machine. Make sure the learner has pushed to GitHub first, and consider asking Skillable support for alternatives.

Common problems

Can’t sign in or can’t see the class

  • Is the learner using the same email GA enrolled? Each email can only have one account.
  • Has the class started? Labs appear when the class starts.
  • Is their enrollment status Enrolled?
  • Don’t let them create a new account. Send their name and email to the program’s CSM.

Lab won’t launch

  • Pop-ups blocked: the lab opens in a new window. Allow pop-ups for the TMS site.
  • Corporate network or VPN: ask them to run the connection test at . If it fails, try a different network or turn off the VPN if their employer allows it.
  • Launch limit reached: contact the lab admin.

Lab is slow or laggy

  • One learner: their network. Try a wired connection, close other tabs, turn off VPN if allowed.
  • Several learners in the same location: contact Skillable support and that location’s IT team at the same time.

Learner lost their work

  • If they pushed to GitHub: git clone (fresh machine) or git pull and continue.
  • If they didn’t: the work on the machine can’t be recovered after End, Cancel or an expired save. Use it as a teaching moment for the whole class, not just the learner.

Lab timer is about to run out

  • The learner should extend when the warning appears.
  • If extending isn’t available: push to GitHub now, then relaunch.

Learner sees End but not Save and Close

  • That lab isn’t set up to save. Push to GitHub before exiting.

Learner chose End or Cancel on a saved lab

  • The machine is gone and the next launch starts fresh. Have them re-clone from GitHub and re-run setup (gh auth login, reinstall packages).

Tool problems on the machine

Symptom Likely cause Fix
git push asks for credentials or fails Not signed in to GitHub on this machine gh auth login
A Python package is missing Not in the base image, or added on a previous fresh machine pip install it, and tell Lab admin if every learner needs it
A tool is missing or the wrong version for everyone Base image issue Lab admin. Don’t have learners install workarounds unless told to
A tool such as Claude Code asks to sign in instead of offering the preset key API key not present in this session Open a new terminal and try again. If it persists, relaunch the lab, then contact the lab admin
A tool such as Claude Code stops with a usage or limit error The program’s API usage limit has been reached Contact Lab admin

More about keys and variables is in the FAQ.

Helping a learner directly

Use Monitor Labs to watch a learner’s screen or take control of their lab. Steps and etiquette are on During class.

Who to contact

Issue Contact
Learner can’t sign in, or isn’t on the roster The program’s CSM
Tool missing, VM broken, lab settings, launch limit, API limit Lab admin
Lab instruction errors The LED or SME for the course, who sends the fix to Lab admin
Whole platform down Check , then tell Lab admin
Platform problems, or any lab issue when the lab admin isn’t available (for example, UK daytime deliveries) GA’s Skillable priority support address (below)
Urgent during a live class The program’s CSM, who escalates to Lab admin if needed

During the lab admin’s working hours, route issues through GA so there’s one thread and one record.

Before you escalate, have ready: the lab instance ID (from the lab’s Help panel), the learner’s name, how many learners are affected, what you’ve tried, and a screenshot.

Contact Skillable support

GA has priority support with Skillable, with our own support address. Use it for platform problems: labs that won’t launch, outages, slow or broken machines, and anything urgent when the lab admin isn’t available.

  1. Email GA’s priority support address first: . If a live class is blocked, put LIVE CLASS in the subject line.
  2. Only if you can’t reach anyone, open a ticket on Skillable’s support site, . Support runs 24/7.
  3. Tell the lab admin what you sent and any reference number, so it can be followed up during GA hours.

Changes to a lab always go to the lab admin, not Skillable. Lab content and settings are GA’s.

Include in every message:

  • Lab instance ID for each affected learner (ask the learner for a screenshot of the Help panel while the lab is still open)
  • Class page link and learner names, if you don’t have instance IDs
  • How many learners are affected
  • What you expected and what happened, with screenshots and steps to reproduce
  • Whether it’s constant or intermittent, and what you’ve already tried
  • For performance issues: learner location, VPN or proxy use, data center (from the Help panel) and connection test results
