Activities, checks and scoring

How to specify questions, automated checks and scoring for the lab admin to build.

Audience
LEDs and SMEs
Time
8 min read

Activities are built in Studio by the lab admin. Your job is to describe each one in your draft, where it should appear. One simple way is an HTML comment under the activity token, which learners never see:

@lab.Activity(PushCheck)
<!-- ACTIVITY PushCheck: automated check. Confirms the learner's latest commit is pushed.
     Points: 1. Correct: "All commits pushed." Wrong: "You have commits that aren't pushed. Run git push." -->

For every activity, include: what it checks, the question and answers (for questions), the points, and the feedback for right and wrong answers.

Questions

  • Multiple choice: one or several correct answers.
  • Short answer: exact match or pattern (regex) match, optionally case-sensitive.

Automated checks

A script that checks the learner’s environment: does the file exist, is the service running, is the repository there, are all commits pushed.

  • Linux machines: Bash
  • Windows machines: PowerShell or the Windows command shell
  • Cloud subscriptions: PowerShell, Python, C# (Azure) or JavaScript (AWS)
  • A check passes by returning true or false, or can award partial credit.
  • A check can also show the learner a pop-up message.

You can describe the check in plain language, or include a script if you have one. The lab admin will adapt it. For example, in Bash:

cd ~/project 2>/dev/null || { echo "Project folder not found"; echo false; exit; }
if git status -sb | grep -q "ahead"; then
  echo "You have commits that aren't pushed yet. Run git push."
  echo false
else
  echo "All commits pushed."
  echo true
fi

Check which operating system the lab uses with the lab admin before you write a script.

Options to ask for

Option Ask for it when
On-demand evaluation Learners select a button to check their work. The default for teaching labs
Allow retries It’s practice, not assessment
Block page navigation until passed A later step breaks if this one isn’t done
Required for submission It’s a must-do item
Show results in reports You want the result in the lab record for CSMs
Correct and incorrect feedback Always. Tell learners what to fix

Scoring

If the lab is scored, include these decisions in your draft:

  • The passing score for the lab
  • A value for each scored activity. Unscored activities count as practice
  • What learners see at the end: nothing, their score, or a full breakdown
  • Whether it’s an exam-style lab: with on-demand evaluation turned off, activities are only scored when the lab is submitted
  • Any outcomes: for example, a wrong answer sends the learner to a review page

Scoring is decided per program, with the client. Check with the program’s CSM before you design a scored lab.
