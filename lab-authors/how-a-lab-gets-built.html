The workflow

  1. The SME writes the tech requirements. Every tool, pinned package, cloud service, role, website and credential the labs need. See Write the tech requirements.
  2. The LED writes the instructions in Markdown, using their usual lesson or lab template, and adds Skillable syntax from the Markdown reference. The SME checks technical accuracy.
  3. The LED specifies the activities. Questions, automated checks and scoring, described in the draft. See Activities and scoring.
  4. You send it to the lab admin. The Markdown file, the tool list and the activity specs.
  5. The lab is built in Studio, by the lab admin or with you in a working session (below). That means building or updating the machine image, loading your instructions, building the activities and publishing the lab.
  6. You review it in a real launch. Skillable syntax only renders inside a running lab, so this is the only true preview. Contractors may test it too. See Test a lab.
  7. Fixes go back to the lab admin as updated Markdown, until the lab is ready.

Build in Studio

GA has four Studio licenses. Lauren holds one as admin and builder. The other three rotate to SMEs, LEDs or instructors while they’re actively building a course.

  1. Ask for a working session. Say what you’re building and what needs to change on the machine.
  2. The lab admin sets up the course shell and gives you one of the shared Studio licenses.
  3. You install and customize inside the machine: tools, packages, settings and files.
  4. The lab admin captures your changes and saves them to the lab image, so every learner launch includes them.
  5. The license goes back to the pool when the build is done, ready for the next person.

Not building hands-on? You don’t need Studio. Send your Markdown and tech requirements, and the lab admin will build it.

What to send the lab admin

Lead times

What Minimum notice
New lab on an existing machine image 3 days
New tool or package on the machine 3 days
New machine image (different operating system or major toolset) 5 days
Instruction fixes, reworks and setting changes 24 hours
A live cloud platform (Azure, AWS, GCP) inside labs Talk to Lab admin early. It can take 1 to 2 weeks

For a new program, aim to hand over final instructions 14 days before the session and have the lab reviewed 7 days before. The launch checklist shows where this fits.

Write in your own editor

Any Markdown editor works. VS Code is a good choice. Its preview will show standard Markdown, but Skillable’s own syntax (click-to-type text, callout blocks, @lab tokens) only renders in a running lab. Don’t worry if the preview looks odd.
