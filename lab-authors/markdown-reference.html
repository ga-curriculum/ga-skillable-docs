Quick reference

You already write lab instructions in Markdown, using your own lesson and lab templates. Keep doing that. This page lists what to add so your Markdown works in Skillable: page breaks, check boxes, click-to-type commands, callouts and tokens. For everything else, see Skillable’s Markdown syntax guide.

The essentials for every GA lab

Five additions turn ordinary Markdown into a GA Skillable lab:

Add Syntax Why
Page breaks between tasks === on its own line One task per page, with a Next button
Check boxes on steps 1. [] Do the thing Learners track progress, and TMS reports it
A save alert where a session ends > [!Alert] Commit and push to GitHub before you leave. Lab machines are disposable
Hidden spoilers > [+Hint] Stuck? Expand for the answer. Learners try first, then reveal
The lab instance ID in a footer @lab.LabInstance.Id The first thing anyone needs when a learner asks for help

Standard Markdown (headings, bold, italics, lists, tables, links and images) works as you’d expect, and so does HTML.

Pages and layout

Syntax What it does
=== on its own line Page break. Ends the page and adds a Next button
--- on its own line A horizontal line on the same page
> text A block quote
- [] step or 1. [] step A task check box. TMS progress is the percentage ticked

No space between the brackets. GitHub-style - [ ] doesn’t become a check box in Skillable.

Interactive text

Syntax What learners get
++text++ Click to copy to their clipboard
+++text+++ Click to type into the machine, at the cursor
++++text++++ Copies and types

Code blocks

Put the language after the opening fence: the shell learners use, such as ```PowerShell or ```bash, or ```python, or ```text for plain output. Add one of these to the language to change how the block behaves:

Modifier Effect
-nocopy Highlighted, but no copy button. Use it for expected output, and for code learners should type themselves
-wrap Long lines wrap instead of scrolling
-linenums Adds line numbers
-nocolor No syntax highlighting
-notab Hides the language tab
-nocode No highlighting, no tab, not copyable 
```bash-nocopy
git add .
git commit -m "describe what changed"
git push
```

Run a command for the learner

Syntax What it does
@[Label](`command`){PowerShell} Runs a PowerShell command in the background
@[Label](`command`){PowerShell visible} Runs it in a visible window
@[Label](`command`){Shell} Runs a command shell command in the background
@[Label](`command`){Shell visible} Runs it in a visible window

These need integration services on the machine. Check with the lab admin before you rely on them, and use them sparingly: learners should still know how to open a terminal.

Callout blocks

> [!Note] Always visible.
> [!Knowledge] Collapses after 4 lines, with a "more" link.
> [!Alert] Important. Shown inline, hard to miss.
> [!Hint] A nudge.
> [!Help] Extra help.

For an expandable version, use [+Note], [+Knowledge], [+Alert], [+Hint] or [+Help]. The first line shows and the rest stays hidden until the learner expands it:

> [+Hint] Stuck? Expand for the answer.
>
> Run git status to see which files changed.

Links, images and video

Syntax Behavior
[text](url) Opens in a new window
^[text](url) Opens in a dialog over the lab
<[text](url) Opens in the lab’s portal window (on machine labs, a new window)
!IMAGE[alt text](url "title") An image
!IMAGE[alt text](url){600} An image 600 pixels wide ({600x400} sets both)
!video[text](youtube-url) An embedded YouTube video. Keep it to 30 to 60 seconds
help[text](url), hint[text](url), knowledge[text](url) Links styled with an icon

Reuse a block on every page

Define the content once on page 1, then drop it in wherever you need it. Handy for a standard save reminder or an instance ID footer on every page.

>[save-reminder]: **Before you leave this lab:** commit and push to GitHub, then check the commit is there.

!instructions[][save-reminder]

To pull in Markdown hosted on GitHub, use [!include [label](raw-github-url)]. The lab shows whatever is at that URL, so a change there changes the lab.

What Skillable doesn’t render

Some things that work on GitHub or in VS Code won’t work in a lab:

Doesn’t work Use instead
Mermaid diagrams An image of the diagram (!IMAGE[...])
HTML <details> and <summary> collapsibles An expandable callout, such as > [+Hint]
GitHub-style check boxes, - [ ] - [], with no space

Replacement tokens and variables

Tokens are filled in when the learner launches the lab.

Token Gives you
@lab.User.FirstName The learner’s first name
@lab.User.Email The learner’s email
@lab.LabInstance.Id This lab run’s ID. Put it in a footer
@lab.VirtualMachine(Name).Username and .Password Sign-in details for a machine
@lab.CtrlAltDelete Sends Ctrl+Alt+Del to the machine
@lab.KeyCombo(label)[codes] A button that sends a key combination. Test it before publishing
@lab.Activity(Name) Places an activity (a question or check)

Values learners enter

Token What it does
@lab.TextBox(name) A box the learner types a value into
@lab.Variable(name) Shows that value later in the lab
@lab.MaskedTextBox(name) Hides what’s typed. It isn’t encrypted, so never use it for real secrets
@lab.DropDownList(name)[a,b,c] A dropdown the learner chooses from
@lab.EssayTextBox(name) A larger box, up to 5,000 characters

Cloud labs have their own tokens for each learner’s cloud sign-in details. See Cloud services, access and credentials.

These tokens are not environment variables. Environment variables live inside the machine, in the terminal. See the Instructor FAQ.
