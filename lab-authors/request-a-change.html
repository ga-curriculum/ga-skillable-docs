Request a lab change

Every change to a lab is made in Skillable Studio. A clear request with enough notice gets done right the first time.

Audience
LEDs, SMEs, instructors and CSMs
Time
5 min read

How to request a change

Email the lab admin at with:

  1. Program and lab name. Which lab, and which session it’s used in.
  2. What should change. Be specific: the exact text, step, tool or setting.
  3. Why. What’s broken, or what the curriculum now needs.
  4. When it’s needed. The session date it has to be live for.
  5. Who’s affected. One cohort, or every program using this lab.
  6. Supporting material. Updated Markdown, a screenshot of the problem, or the lab instance ID if it’s a bug.

For instruction changes, send the updated Markdown rather than a description of the edit.

Recommended notice

Change Examples Minimum notice
Small instruction fix Typo, wrong command, unclear step 24 hours
Instruction rework New steps, reordered pages, new activities or checks 24 hours
Lab setting Duration, timeouts, save behavior, visibility 24 hours
New open source tool or package on the VM A Python library, CLI tool or VS Code extension 3 days
New lab A new lab built on an existing image 3 days
New VM image A different operating system or a major toolset change 5 days
New cloud platform inside labs Live Azure, AWS or GCP environments Talk to Lab admin as early as possible. This can take 1-2 weeks

Urgent fixes during a live class are handled as soon as possible. Anything that breaks a live session goes through When a lab misbehaves first.

When a change reaches learners

How a change reaches learners depends on how the lab behaves.

  • Fresh-machine labs: changes apply the next time a learner launches the lab. Every new launch picks up the latest version.
  • Saved or persistent labs (learners keep one machine for a period): a learner’s saved machine is a copy made at launch. Changes to the VM image don’t reach machines that are already saved. Instruction changes may also not appear until the learner relaunches. Plan image changes for before the first launch, not midway through a persistent block.
  • Mid-cohort changes should be tested in a real launch before learners see them, and instructors should know what changed before the session.

What not to do

Don’t ask learners to install workarounds for a missing tool without checking with the lab admin. The next fresh machine won’t have it, and it may hide a problem every learner will hit.

Don’t edit instructions in a test lab and expect them to stick. Test sessions are disposable too.

Don’t contact Skillable to change a lab. Lab content and settings are GA’s. Skillable support is for platform issues.
