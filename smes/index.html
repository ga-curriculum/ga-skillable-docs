SME onboarding

You define the lab environment: the tools, packages, cloud services, access and credentials that make every lab work on day one.

Audience
Subject matter experts
Time
About 30 minutes

Your first 30 minutes

  1. Sign in to TMS. You’ll test every lab in a real launch. 4 min
  2. Read How a lab gets built: where your requirements fit, and the lead times. 5 min
  3. Read Write the tech requirements. This is the document the lab admin builds from. 8 min
  4. If the course uses cloud services, read Cloud services, access and credentials. 8 min
  5. Launch a lab and check the tools you specified are there, at the right versions. 5 min

Building the machine yourself? Set up a Studio working session and you’ll get one of the shared Studio licenses for the build.

Five things to know

1

The image is the environment

Anything not built into the lab image has to be installed by learners on every fresh machine. Ask for it in the requirements, or install it yourself in a Studio working session with the lab admin.

2

Pin your versions

Give exact versions for languages and packages, and say which sessions need what.

3

A blocked website is the top delivery-day failure

List every outside domain the labs reach, from GitHub to package indexes to cloud APIs.

4

Credentials never go in chat or on slides

Keys are built into the lab image or set at launch. The lab admin arranges this from your requirements.

5

Test on Skillable, with a learner account

A lab that works on your laptop, or with an admin account, can still fail for learners.
